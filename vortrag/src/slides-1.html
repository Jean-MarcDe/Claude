AI, Machine Learning, LLM: Einordnung der Begriffe

Artificial Intelligence (AI, deutsch KI): Sammelbegriff für Systeme, die Aufgaben lösen, für die man Intelligenz voraussetzen würde.

01
Wie ein LLM funktioniert

Vom einzelnen Neuron bis zum System, das Tools aufruft. Vorkenntnisse sind nicht erforderlich.

Machine Learning

Programmierte Regeln und gelernte Parameter

Klassische Software

Ein Mensch schreibt die Regel

if betreff.contains("Gewinn")
   and absender not in kontakte:
    return SPAM

Exakt, nachvollziehbar, testbar. Deckt nur die Fälle ab, die jemand vorhergesehen hat.

Machine Learning

Ein Suchverfahren findet die Regel

# 1 Mio. Mails, jede mit Label
model = train(mails, labels)
model(neue_mail)  # → 0.97 SPAM

Die Regel besteht aus Zahlen, den Parametern. Kein Mensch hat sie geschrieben, und sie lassen sich nicht direkt lesen.

Ob ein Modell eine Aufgabe beherrscht, lässt sich nur durch Tests mit bekannten Antworten feststellen. Eine Spezifikation, der man es entnehmen könnte, gibt es nicht.
Neural Network

Ein Neuron: eine Funktion mit drei Parametern

z = w₁x₁ + w₂x₂ + b

ŷ = σ(z)

Weights gewichten die Eingaben, der Bias verschiebt die Summe. Beide zusammen sind die Parameter.

Die Activation Function ist nichtlinear. Ohne sie ließe sich jedes Netz, unabhängig von der Zahl der Layer, zu einem einzigen Layer zusammenfassen.

Neural Network

Neural Network: Neuronen in mehreren Layern

10¹¹

Größenordnung der Parameterzahl eines aktuellen großen LLM

Jede Linie ist ein Weight. Frühe Layer erkennen einfache Muster, spätere kombinieren sie zu abstrakteren.

Hyperparameter (Anzahl der Layer, Learning Rate) legt ein Mensch vor dem Training fest. Sie werden nicht gelernt.

Training

Training: vier Schritte, milliardenfach wiederholt

1 · Forward Pass

Vorhersage berechnen

Die Eingabe durchläuft alle Layer. Das Ergebnis ist ŷ.

2 · Loss

Fehler messen

Eine einzige Zahl gibt an, wie weit ŷ vom Sollwert y abweicht.

3 · Backpropagation

Fehleranteil bestimmen

Für jeden Parameter wird berechnet, wie stark er zum Fehler beigetragen hat.

4 · Gradient Descent

Parameter anpassen

Jeder Parameter wird ein kleines Stück in die Richtung verändert, die den Loss senkt.

Der Loss ist die vollständige Spezifikation des Trainingsziels. Was er nicht misst, lernt das Modell nicht gezielt.

In der Praxis wird der Gradient aus einem kleinen zufälligen Batch geschätzt und nicht aus allen Daten berechnet. Das Verfahren heißt Stochastic Gradient Descent.

Training

Gradient Descent: schrittweise zum Minimum

w ← w − η · ∂L/∂w

Der Gradient ist die Steigung des Loss bezüglich eines Parameters. Er zeigt in Richtung des Anstiegs, daher wird der Parameter in die Gegenrichtung verändert.

Die Learning Rate η ist die Schrittweite.

  • η = 0,05: nähert sich dem Minimum langsam
  • η = 0,5: erreicht das Minimum in einem Schritt
  • η = 0,9: pendelt um das Minimum
  • η > 1: divergiert

In einem LLM geschieht das für 10¹¹ Parameter gleichzeitig.

Training

Backpropagation: Gradienten aller Parameter

Chain Rule

Die Ableitung einer verketteten Funktion ist das Produkt der Ableitungen ihrer Glieder. Backpropagation wendet diese Regel Layer für Layer an.

Ein Durchlauf genügt

Ein einziger Backward Pass liefert die Ableitung für alle Parameter. Der Rechenaufwand entspricht etwa einem zweiten Forward Pass.

Abgrenzung

Backpropagation berechnet die Gradienten. Gradient Descent verwendet sie, um die Parameter anzupassen.

Training eines LLM

Trainingsziel: Next-Token Prediction

The·nightly·run·failed·because·it·?

Self-Supervised Learning

Der Sollwert steht im Text selbst: Das nächste Token wird verdeckt, vorhergesagt und verglichen. Labels von Menschen sind nicht nötig, daher lassen sich sehr große Textmengen als Trainingsmaterial verwenden.

Cross-Entropy Loss

L = −log p(richtiges Token)

Der Loss ist hoch, wenn das Modell dem tatsächlich folgenden Token eine geringe Wahrscheinlichkeit gegeben hat.

Drei Phasen

Pretraining vermittelt Wissen. Fine-Tuning trainiert das Frage-Antwort-Format. RLHF prägt Ton und Hilfsbereitschaft, aber auch die Neigung zuzustimmen.

Das Trainingsziel ist eine plausible Fortsetzung des Textes. Ob eine Ausgabe sachlich richtig ist, wird dabei nicht geprüft.
Von Text zu Vorhersage · 1

Tokenization: Text wird in Tokens zerlegt

Ein Token ist ein Textstück aus einem festen Vocabulary von etwa 100.000–200.000 Einträgen.

Das Vocabulary entsteht durch Byte-Pair Encoding: Häufige Zeichenfolgen werden zu einem Token zusammengefasst. Häufige Wörter sind ein Token, seltene bestehen aus mehreren.

Das Modell verarbeitet Tokens, keine Buchstaben: Buchstaben zählen und exaktes Rechnen sind daher unzuverlässig. Kosten und Context Window werden in Tokens gemessen. Deutscher Text braucht mehr Tokens als englischer.
Von Text zu Vorhersage · 2

Embeddings: Jedes Token wird ein Vektor

Der erste Layer ist eine Tabelle. Sie enthält für jedes Token eine Zeile mit einigen tausend Zahlen, das Embedding.

Das Training ordnet die Vektoren so an, dass ähnlich verwendete Tokens nah beieinander liegen. Die Position im Vektorraum repräsentiert die Bedeutung.

Das Bild ist eine Projektion auf zwei von tausenden Dimensionen. Einzelne Dimensionen haben keine lesbare Bedeutung.

Auf demselben Prinzip beruhen Semantic Search und RAG: Gefunden wird Text mit ähnlicher Bedeutung, auch wenn er anders formuliert ist.
Von Text zu Vorhersage · 3

Attention: Information zwischen Tokens

Im Beispielsatz bezieht sich it auf run. Attention überträgt diese Information von einer Position zur anderen.

Jede Position hat eine Query (gesuchte Information), einen Key (angebotene Information) und einen Value (Inhalt). Das Ergebnis ist eine gewichtete Mischung der Values.

Attention(Q,K,V) = softmax(QKᵀ/√dₖ)·V

Jedes Token wird mit jedem anderen verglichen. Der Rechenaufwand wächst daher quadratisch mit der Länge des Context.
Von Text zu Vorhersage · 4

Transformer: der gesamte Forward Pass

Attention bewegt Information zwischen Positionen.

Feed-Forward verarbeitet Information an einer Position. Dort liegt der Großteil der Parameter.

Das Ergebnis ist eine Wahrscheinlichkeit für jedes Token im Vocabulary, noch kein Text.

Von Text zu Vorhersage · 5

Sampling: Das nächste Token wird zufällig gezogen

Temperature teilt die Logits vor dem Softmax.

  • T < 1 verstärkt die Unterschiede: Das wahrscheinlichste Token wird fast immer gezogen
  • T > 1 gleicht die Unterschiede an: Unwahrscheinliche Tokens werden häufiger gezogen
  • Top-p schließt die unwahrscheinlichsten Tokens vom Ziehen aus
Dieselbe Anfrage kann verschiedene Antworten liefern. Ein einzelner Durchlauf ist daher wenig aussagekräftig. Wichtige Anfragen sollten mehrfach ausgeführt werden.
Von Text zu Vorhersage · 6

Autoregression: Die Ausgabe wird Teil der Eingabe

Kosten

Jedes neue Token erfordert einen Forward Pass über den gesamten Context. Output-Tokens sind deshalb teurer als Input-Tokens.

Fehler

Ein früher Fehler steht danach im Context und beeinflusst alle folgenden Tokens. Fehler pflanzen sich fort.

Herkunft

Der Context besteht nur aus Text. Vom Modell erzeugter Text, zugelieferte Inhalte und Anweisungen sind technisch nicht unterscheidbar.

Wissen des Modells

Zwei Wissensquellen: Parameter und Context

Parameter · Langzeitwissen

Im Training gelernt, danach eingefroren

  • Endet am Training Cutoff
  • Enthält nichts Internes: weder Code noch Prozesse des Unternehmens
  • Ungenau: verdichtete Muster, keine wörtlich gespeicherten Texte
Context · Arbeitsgedächtnis

Was in diesem Request mitgeschickt wird

  • Aktuell, exakt, wörtlich zitierbar
  • Begrenzt und kostet Tokens
  • Nach dem Request nicht mehr vorhanden
Inference verändert die Parameter nicht: Das Modell lernt nicht aus der Nutzung. Memory-Funktionen beruhen auf Text, den der Harness erneut in den Context einfügt.
Wissen des Modells

Context Window: begrenzt, geteilt, bei jedem Request neu gesendet

Compaction. Ist das Fenster fast voll, ersetzt der Harness den bisherigen Verlauf durch eine Zusammenfassung. Details gehen dabei verloren.

Lost in the Middle. Je voller das Fenster, desto unzuverlässiger nutzt das Modell den Inhalt, am schlechtesten den in der Mitte.

Geteilter Platz. System Prompt, Tool-Definitionen und Instructions belegen Platz, bevor die erste Eingabe erfolgt.

Hallucination

Kein Schritt im gesamten Verfahren prüft eine Aussage gegen die Wirklichkeit.

Eine Hallucination entsteht durch denselben Mechanismus wie eine richtige Antwort. Er wird dort angewendet, wo die Trainingsdaten das Ergebnis nicht festgelegt haben.

Gegenmaßnahmen
  • Die Quelle in den Context geben (Datei, Dokumentation, RAG)
  • Tools rechnen, suchen, ausführen lassen
  • Belege verlangen und prüfen
Reasoning

Reasoning: Zwischenschritte als Tokens

Ein Forward Pass hat eine feste Rechentiefe. Für mehrstufige Probleme reicht sie nicht aus.

Reasoning-Modelle erzeugen zuerst Zwischenschritte, vergleichbar mit einem Notizblatt, und verarbeiten sie per Attention erneut. Erst danach folgt die Antwort.

Der Reasoning Effort (Thinking Effort) wird pro Aufgabe eingestellt und ist keine feste Eigenschaft des Modells.

AufgabeHoher Reasoning Effort
Architekturentscheidung, Debugging über mehrere Dateiensinnvoll
Mehrstufige Planung, Abwägungensinnvoll
Umformatieren, Nachschlagen, Boilerplatenur Mehrkosten
Thinking Tokens werden als Output abgerechnet, also zum höchsten Preis, und sind oft nicht sichtbar.
Modell und System

Der Harness: Das Modell führt nichts selbst aus

Ein Tool Call ist nur strukturierter Text: Name plus Argumente. Der Harness entscheidet, ob er ausgeführt wird.

Agentic Loop: beobachten → entscheiden → handeln → Ergebnis lesen → wiederholen, bis die Aufgabe erledigt ist.

Viele Verhaltensweisen, die dem Modell zugeschrieben werden, sind Einstellungen des Harness. Dasselbe Modell verhält sich in Copilot, in Claude Code und im Chat unterschiedlich.
